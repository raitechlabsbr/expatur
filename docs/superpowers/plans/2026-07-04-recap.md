# Plano de Implementação — Feature Recap (relatório de reservas)

> **Para workers agênticos:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development
> (recomendado) ou superpowers:executing-plans para implementar tarefa a tarefa. Os passos usam
> checkbox (`- [ ]`).

**Objetivo:** Portar a feature Recap (relatório de reservas com colunas configuráveis + exclusão em
massa) do `docs/monolito.html` para a plataforma, rodando sobre os dossiês que a plataforma já tem,
**dropando** o plumbing Cloudflare/D1 e o import CSV.

**Arquitetura:** Port fiel de transcrição de dois IIFEs do monólito para `src/js/recap.js`, com
**remoções cirúrgicas** (bloco Cloudflare + delete D1). O Recap é um **feature-flag ON por default**
(`window.__RECAP_ENABLED = true`) que injeta um `#recap-view` dentro de `#section-bookings` e
substitui o conteúdo de Bookings — fiel à produção, sem botão de toggle. Prefs de coluna em
localStorage.

**Tech Stack:** Vanilla JS (ES modules, bridges `window.*`), Vite (`npm run build`). Sem backend
novo, sem migration.

## Global Constraints

- **Sem test runner.** Verificação = `npm run build` verde + checagem runtime no browser. Não
  inventar vitest/jest.
- **Fonte de verdade do código portado:** `docs/monolito.html`, nos intervalos citados. Portar
  **verbatim**, removendo/ajustando SÓ o que cada task manda.
- **Dropar todo o Cloudflare/D1:** `EXPATUR_API`, `_apiOn`, `_apiHdr`, `_recapApiPushRow`,
  `_recapApiLoad`, `_recapPrefsPush`, `_recapPrefsLoad`, `_recapCloudResync`, `_recapRefreshCloud`,
  `_migrateAllToD1`, `_deleteD1`. Nenhuma chamada de rede.
- **Dropar o import CSV** (o IIFE `_recapImpInit` ~77723 e `_recapImportPick`) — depende do DXR.
- **Feature flag:** `window.__RECAP_ENABLED` inicia `true` (default de produção); `recapEnable`/
  `recapDisable` preservados para reverter.
- **Prefs de coluna:** só `localStorage['expatur_recap_cols']` (remover o `_recapPrefsPush`).
- **`index.html` NÃO muda** (o recap.js injeta `#recap-view` + `<style>` via JS).
- **UI em francês** (rótulos idênticos ao monólito). Comentários de código em português.
- **Encapsular no módulo:** os helpers internos (`_typeLabel`, `_pnrsOf`, `_legRoute`, `_fmtDMY`,
  `_paxDisp`, `_brl*`, etc.) ficam dentro do IIFE do recap.js — não vazar globais que colidam com
  o `app.js`.

## Task 1: `recap.js` — núcleo (render + colunas), sem Cloudflare

Porta o IIFE principal do Recap, removendo o bloco Cloudflare. Deliverable: abrir **Bookings**
mostra o relatório Recap (flag ON) com as 9 colunas configuráveis; `window.recapDisable()` volta à
view de Bookings. Sem bulk delete ainda (Task 2).

**Files:**
- Create: `src/js/recap.js`
- Modify: `src/js/main.js` (import)

**Interfaces:**
- Consumes (já existem na plataforma): dossiês em localStorage (`expatur_dossier_list`,
  `expatur_dossier_<id>`, `expatur_billet_<ref>`), `window._diDealValue` (deal value),
  `window.bookingsRender`, `window.sidebarGo`. **A resolver na implementação:** a fonte do P&L por
  dossiê (`_pnl.ravBrut`/`_pnl.netRAV` no monólito — ver Step 3).
- Produces: `window.__RECAP_ENABLED`, `window.recapEnable()`, `window.recapDisable()`,
  `window._recapRender()`, `window.recapRefresh` (se o monólito exportar), e os handlers de coluna
  `window._recapColToggle(id)`, `window._recapColMove(id,dir)`, `window._recapColsReset()`,
  `window._recapMenuToggle(ev)`, `window._recapMenuClose()`. (Task 2 adiciona `window._recapBulkToggle`.)

`ravBrut:(_pnl && _pnl.ravBrut!=null)?_numBR(_pnl.ravBrut):null` e
`ravNet:(_pnl && _pnl.netRAV!=null)?_numBR(_pnl.netRAV):null`, onde `_pnl` é o P&L do dossiê.

- Se existir a mesma fonte de P&L por dossiê (ex.: uma função/cache que o app.js expõe), **reusá-la**.
- Se **não** existir de forma acessível, portar o cálculo do recap se ele for self-contained, OU
  deixar `ravBrut`/`ravNet` caírem para `null` → a célula renderiza `—` (comportamento já previsto:

  caminho foi tomado.** As demais colunas (data, dossiê, deal value via `_diDealValue`, pax, cia,
  PNR, trecho) não dependem do P&L e devem popular normalmente.
